## 术语速查

先看这张表，后文不再重复解释。

| 词 | 意思 |
|---|---|
| **raster** | 把车道、周围车辆、自车状态这些结构化信息，按某组相机参数投影出来的示意图像。**不是真实照片。** |
| **C_d（目标相机组）** | NAVSIM 的 4 个相机：后 `CAM_B0`、前 `CAM_F0`、左 `CAM_L0`、右 `CAM_R0`。本周期所有 raster 都按它渲染。 |
| **F0** | 基线实验：只用目标数据集（NAVSIM）自己的数据训练。 |
| **F1** | 对照实验：F0 再加上「把外部数据集（nuScenes）的结构化信息按 C_d 重新渲成 raster」这一路输入。**F1 与 F0 只差这一个变量。** |
| **X1** | F0 再加上「外部数据集的真实照片 ↔ 外部相机下的 raster」特征对齐。本周期最多做一次小规模试跑。 |
| **PDMS** | NAVSIM 官方闭环评分。本周期主指标，其分项为次要指标。 |
| **open-loop 指标** | 轨迹误差类的开环指标。只能用来诊断，不能替代 PDMS 下结论。 |
| **manifest（样本清单）** | 写死了用哪些 log 和 token 的文件，带 sha256。生成一次之后只读，不再重新抽样。 |
| **H0** | 渲染几何正确性检查：重投影误差、坐标往返误差、故意注入错误能不能被查出来。 |
| **smoke test（冒烟测试）** | 约 50 步的极小规模试跑，只验证管线通不通，**不产生任何科学结论**。 |
| **A1–A5** | 已完成的资产审计报告，见 [docs/audits/](docs/audits/)。 |
| **CP-CODE** | 关键代码改完后必须交给 Joy 的人工检查卡。Joy 明确写 PASS 之前，不 commit、不跑 smoke、不跑正式实验。 |
| **run_id** | 一次实验的身份编号。协议一变就必须换新号，换号后的结果不能和旧结果放在一张表里比较。 |
| **provenance（来源可追溯）** | 这份数据或模型是哪段代码、哪个作业、什么输入产生的，有没有记录。没记录就是 UNKNOWN。 |
| **SD-**\* | 科学决策项。**只有 Joy 能裁决，Agent 一律不得代填。** |
| **G0–G5** | 阶段闸门。不通过就不许进入下一阶段。 |
| **P1-**\*／**P2-**\*／**P3-**\* | 三个阶段各自的任务编号。 |

## 4. 出问题时怎么归类

四个词各有严格含义，**不许混用**：

| 现象 | 归类 | 怎么处理 |
|---|---|---|
| 显存溢出、张量形状不匹配、dataloader 崩、NaN、checkpoint 损坏、作业被队列杀 | **Technical Failure**（技术失败） | 修好重跑；**不产生任何科学结论** |
| A1–A5 有 UNKNOWN 或 BLOCKED、H0 没过、`SD-*` 还没裁 | **BLOCKED**（阻断） | 卡在门口，不进下一阶段；**绝不能写成 `Refuted`** |
| 训练和评测都正常，但 G4 的配对条件有任何一条不满足 | **INVALID**（无效） | 不上会、不进主叙事；**两臂一起重跑**，不许只重跑一臂 |
| 训练正常收敛，F1 与 F0 出现任意幅度的差异 | **Pilot observation**（观察） | 原样报告方向和差值；科学结论恒为 `Inconclusive` |

**铁律**：实验开始之后，不得因为初期结果不理想而私自修改协议。任何协议变更都必须新开 run_id、在 registry 里写清原因，并声明该 run 与之前的 run **不可配对比较**。
