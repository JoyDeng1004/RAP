## 一、会议起点：要解决什么问题

**对应转录：09:17–09:20；09:27–09:36。**

Joy 希望确认：为了训练适用于一个 target camera rig 的 planner，究竟能把 target 数据量降到多低，以及应该选择怎样的学习方法。

初始资源假设为：

- external 侧有丰富的驾驶数据，可以利用其中的结构化场景信息、planning GT，也可能进一步利用真实 RGB。
- target 侧真实数据有限。
- 一条基本思路是：用大量结构化数据承担 planning 学习，用少量 target real/raster pairs 学习视觉对齐。

佐藤反复澄清，**我们最终服务的是事先选定的 target rig**。例如以 NAVSIM 为 target，则最终在其测试集上评估；external 数据的意义，是为这个 target planner 提供知识。

这与“只在 source rig 上训练，到测试时才知道另一个 rig，并要求模型直接泛化”的问题不同。会议前半段的沟通反复，主要来自这两个设置被交替使用。

### 1. 本研究的基本设置

1. 训练前知道 target camera rig 的配置。
2. 将 external metadata 按 target rig 渲染成 raster。
3. 用这些带 planning supervision 的 target-view raster 学习。
4. target 真实训练图像的数量可以为零、很少或更多；在固定 target 测试集上评价。

**需要分清“数据来自哪里”和“从哪个 camera rig 观察它”**：external 场景可以被渲染成 target-view raster。因此，“planning 只面向 target rig”不等于“planning 只能使用 target dataset 的场景”。

### 2. Zero-shot / few-shot 的精确定义

| 设置 | Target 真实训练图像 | Target rig 参数 | 本次讨论的含义 |
|---|---:|---|---|
| Zero-shot | 0 | 训练时已知 | 不使用 target real training images，但仍可按 target rig 渲染 external metadata |
| Few-shot | 少量 | 训练时已知 | 可利用少量 target real/raster pairs 做 alignment；有相应 GT 时，也可计算 target real planning loss |

佐藤明确指出：**zero-shot 不意味着不知道 target calibration**。没有 target rig 条件，就无法进行所讨论的 target-view rasterization。

还要区分两种 zero-shot 方法：

- **基本 raster-only 方案**：没有 target real 图像，因此没有 target real–raster alignment；训练后在 target real 图像上测试。
- **后续讨论的 external-alignment 方案**：仍然可以不使用 target real 图像，但加入 external real/raster alignment。它是否能改善 target zero-shot，是待验证的问题。

因此不能把前半段的“zero-shot 没有 similarity loss”，扩写成所有候选方法都禁止 external alignment。另一个尚需写清的协议边界是：除 calibration 外，是否允许使用 target 训练集的 metadata/标签；本次转录主要明确了真实训练图像数量。

## 二、Camera rig 的定义，以及 rig 变化为何影响 planning

**对应转录：09:20–09:44。**

### 1. 会上确认的工作定义

Camera rig 包括：

- **相机内参（intrinsics）**：会上将 FOV、distortion 及其描述归在这一侧。
- **相机外参（extrinsics）**：安装位置、高度、方向，以及多相机的相对位置关系。
- **相机数量（camera count）**：多相机系统需要额外明确。

这里是研究范围的分类，不应把 FOV、projection model、distortion 当成与“内参”完全并列的独立大类。实际实现仍需明确相机模型与标定字段。

### 2. 佐藤的几何解释

即使观察的是同一个三维世界，只要相机安装高度或角度不同，同一三维点在二维图像上的位置就会变化。佐藤用针孔成像示意，说明地面上的人及其脚部投影如何随相机与地面的位置关系改变。

这会影响模型如何从图像推断距离，以及如何把图像信息关联到 BEV/grid 等空间位置。

他还举出另外几类潜在不一致：

- 图像尺寸、图像位置与 positional embedding（PE）的关系；
- 相机数量和 camera ID 的对应；
- 训练只见过一种 rig，测试却使用另一种输入组织方式。

**“两套系统都有 360° coverage”不足以推出它们可以直接互换。** Coverage 描述可见范围，不能替代几何和模型接口的一致性。

这些是佐藤对直接换 rig 风险的解释，并非今天已有实验验证的性能结论，也不是断言所有架构都无法跨 rig。

### 3. 对汇报 scope 的修正

Joy 原本希望围绕 FOV / projection model 的变化来收窄问题。佐藤要求先回答：**它们在我们实际采用的训练与测试设置里，究竟造成哪一个困难？**

后续介绍应先给出 target 专用、target calibration 已知、target real 有限的设置，再说明研究中要处理哪些 rig 差异。原 PPT 中“FOV / projection model 最具挑战”的表述，不能直接作为本次已确认的研究结论。

## 三、RAP 的价值，与佐藤希望看到的主结果

**对应转录：09:44–09:52。**

Joy 说明选择 RAP 的理由：只要有 metadata，就可以按目标 camera rig 大量构造 raster，同时保留相应的 planning/trajectory GT，不必获得相同场景的 target RGB。佐藤认可这一价值。

但佐藤强调，最重要的出发点是：

**External 数据丰富，而 target 数据的需求量正是研究对象；研究要证明 external 的知识能够被 target 有效利用。**

表达上应把 Old/New 改为 **External/Target**，因为数据新旧不决定其研究角色。

### 主结果的两条轴

| 实验轴 | 固定什么 | 改变什么 | 要回答的问题 |
|---|---|---|---|
| Target 数据效率 | External 数据预算 | Target 真实训练数据量 | 同等 target 数据量下，external 知识能带来多少收益？达到某个性能需要多少 target 数据？ |
| External 数据扩展收益 | Target 数据预算 | External 数据量 | 增加 external 数据是否持续提高 target planning 性能，何时趋于饱和？ |

佐藤用示意曲线说明：提案方法可能在 zero-shot 时已有一定表现，加入少量 target 数据后快速提高；也可能随 external 数据增加而改善。**这两种走势是希望检验的假设，不是已有结果。**

不要只围绕某个预定的 few-shot 数量做一次胜负比较。实验资源不够画密集曲线时，用若干代表条件组成结果表也可以。

图中的纵轴是概念性的“accuracy/performance”。正式实验应写实际 planning 指标；若沿用项目当前 NAVSIM 评估，可沿用既有 PDMS 及分项，不能把示意图当成今天已经定下的新指标。

## 四、方案 A / B：External RGB 的 alignment knowledge 值不值得用

**对应转录：09:45–10:07。**

### 1. 两个方案的实际区别

| 部分 | 方案 A：基本 synthetic transfer | 方案 B：进一步利用 external alignment |
|---|---|---|
| External metadata/GT | 用于 target-view raster planning | 同样利用 |
| Target real/raster pairs | 有数据时做 target alignment | 有数据时做 target alignment |
| External real/raster pairs | 不使用 | 在各自 external rig 下建立对应，尝试向 target 迁移对齐知识 |
| 新增问题 | 大量 raster 能否降低 target 数据需求？ | External rig 的对齐知识能否帮助 target zero-/few-shot？ |

方案 B 中，external real 应与**同一场景、相应 external rig 下的 raster**形成 pair；不能把它不加处理地当成 target-view raster 的逐像素对应。

蒸馏、joint training 是讨论过的实现候选，具体共享哪些模块、怎样处理 rig、loss 如何加权，今天尚未最终定案。佐藤最初说 A/B 的目标相同，并不意味着两者的数据路径完全相同；external RGB 的附加利用在后续才被展开说明。

### 2. 关于“all-data 是最强 pattern”的修正

Joy 转述池畑的思路：既然 external RGB 丰富，不应将其中的视觉对齐知识全部丢弃。

佐藤没有否定做实验，但反复指出：

- “数据更多”不足以解释为什么 target 性能一定提高。
- 需要说明多出来的数据传递什么知识，以及是否可能破坏 target 的学习目标。
- 只有实验比较后，才能说某个 all-data 配置更强。

Joy 提出约 **1000 小时 external vs 10 分钟 target** 的例子，担心少量 target 不足以学好 visual alignment。这是说明数据悬殊的假设性例子，比例约为 6000:1，并非今天确定的训练预算。

佐藤认可 external alignment 可能是好提案，同时保留对副作用的担心。他在 10:05 左右明确支持尝试，要求加强 reasoning。结论应记录为：

**值得开展比较实验；收益与风险都需要证据；不预设 B 优于 A。**

### 3. 方法新意要落到什么地方

佐藤认为，只把 external metadata 接入原 RAP、改变数据的流向，即使有实验价值，方法层面仍然偏弱。

更有潜力的贡献是：**明确不同 rig 下的 alignment 应如何组织，证明哪些 loss 有利于 target zero-/few-shot、哪些 loss 会造成干扰，并据此提出有依据的多数据集训练方法。**

这是他对新意的判断，不等于已经完成先行工作检索或确认没有类似论文。

## 五、重要边界：External-rig alignment 与 external-rig planning 分开处理

**对应转录：10:08–10:11；手写 Memo 中两个重点标记。**

佐藤将这两个操作明确分开：

1. 在 external camera rig 下学习 real–raster alignment。
2. 在 external camera rig 下计算 planning loss。

他支持研究前者；对后者，他的判断是可能无助于 target 性能，甚至造成冲突。原因是最终 planner 面向固定 target rig，多种 rig 下的投影关系可能对同一个 planner 施加不一致的要求。

### 当前优先测试的数据与 loss 关系

| 输入/数据路径 | Alignment | Planning |
|---|---|---|
| External metadata → **target-rig raster** | 不自动构成 real/raster pair | 用 external 场景的 GT 训练 target-rig planning |
| Target real ↔ target-rig raster | 有配对数据时计算 target alignment | 有对应 GT 时训练 target planning |
| External real ↔ **external-rig raster** | 作为新增 external alignment 候选 | 当前优先方案不加入 external-rig planning loss |

这里“external rig 不进 planning loss”指的是**观察几何/分支的选择**，不是丢弃 external metadata 中的 planning supervision。

手写 Memo 将其记为明确边界；转录中佐藤仍保留“可能”“感觉”等措辞，并马上建议比较各种 loss 变体。因此准确状态是：

**把 planning 集中在 target rig 上，作为当前优先设计；external-rig planning 是否有害，可设置独立消融验证，不能写成已经被证明无效。**

### 原比较表需要一起修正

截图中的“Old Synthetic Raster / New Synthetic Raster”混淆了两个维度：

- 场景 metadata 来自 external 还是 target；
- raster 按 external rig 还是 target rig 渲染。

建议改为明确的“场景来源 × 渲染 rig × 接受的 loss”。否则，external metadata 生成的大量 target-view raster 容易被误记成“少量 New Synthetic”。

原表的 Target-only 行还勾选了 Old Synthetic Raster，与其名称存在解释上的不一致；应核对定义后重画。All-data 的预期排序只能保留为假设。Alignment-only control 也必须定义为“external metadata 不用于新增 planning supervision”，不应声称生成 external raster 完全不需要 metadata。

## 六、新路线：简易 Simulator 与 RAP 联动

**对应转录：10:12–10:22。**

### 1. 佐藤希望寻找怎样的 simulator

佐藤提出：raster 描述的道路、车道线、自车与其他车辆，本身接近一个简化驾驶环境。如果能取得场景状态，就可能按 target camera rig 渲染成 RAP 使用的 raster。

需要优先寻找的是：

- 能提供自车、他车和道路/车道线等状态；
- 能执行行动、推进环境；
- 能提供 reward，最好已有可复用的默认设计；
- 结构简单，教学级或练习用驾驶 RL 环境也可以。

**高保真画面不是要求。** CARLA 和类似驾驶游戏被用作讨论中的参照，不是今天确定采用的平台。佐藤明确说不需要为了漂亮视觉效果选复杂系统。

### 2. 路线一：先完成 RL teacher，再蒸馏到 RAP planner

流程：

**Simulator 内训练 RL policy → 生成驾驶行为/轨迹伪标签 → 按 target rig 渲染场景 raster → 用伪标签训练 RAP planner → 与 target 真实数据适配。**

这里的蒸馏，是把 RL 学到的驾驶行为移入 RAP-style planner，不应擅自补成某种已选定的 feature/KL 蒸馏算法。

**为什么佐藤说 external dataset 可能不再需要？**

在这一候选路线里，simulator 可以提供场景，RL teacher 可以提供行为监督，因而能够替代原来 external logged dataset 承担的部分数据与监督来源。这是根据相邻发言还原的逻辑；它不是“所有数据都不再需要”，也不是决定放弃 external alignment。Target-domain 适配与真实测试仍在讨论中。

### 3. 路线二：让 RAP planner 本身直接参与闭环 RL

佐藤在 10:16–10:18 的推演中修正了说法，最终提出：

**Simulator 状态 → target-rig raster → RAP planner 输出 plan/action → simulator 执行/评价并返回 reward → 更新这个 planner。**

他用“状态 + plan”来说明 planning reward 的输入，举例包括速度、与车道线的关系等。轨迹如何转换为 simulator 可执行动作、reward 如何累积等接口细节，并未在会上定下。

关键区别是：**第二条路线直接训练实际使用的 planner，不以先训练 teacher、再蒸馏为前提。**

佐藤期待这样能让 planner 接受 closed-loop training，从而改善闭环评估；这仍是预期，今天没有相关实验结果。

### 4. 联合训练的“三种 loss / 学习信号”

10:21–10:22，佐藤列出的三部分为：

1. **Simulator/RL 目标**：raster 输入后的 planning 结果由 simulator 评价，提供 reward。
2. **Target real planning loss**：同一个 planner 同时在 target 真实图像上做 planning 学习。
3. **Real–raster alignment loss**：将真实图像和 raster 的特征联系起来。

这不是 metric learning 中的 triplet loss；转录末尾的“triplet learning”在这里应理解为上述三种学习目标的联合。

这条具体联合训练构想包含 target real 数据。不能直接把它当成已定义好的 zero-target-real 协议；若探索零图像版本，需要另行说明哪些项关闭、替代或迁移。

### 5. 研究定位的变化

这会把主问题从 multi-dataset 扩展到 **simulation 与 real 数据的联合学习**。佐藤甚至表示，比起单纯“sim-to-real”顺序迁移，更接近 sim/real 统一训练。

他的判断是，这条路线可能在效果和研究价值上都值得重视；是否有方法差分，仍需调查已有工作。没有决定用 RL 全面替换当前 multi-dataset 路线。

## 七、结尾真正要求调查的事项

**对应转录：10:22–10:25。**

手写 Memo 中不确定的“三件事”，更适合按推进顺序还原：

1. **找可用 simulator，确认能否提取状态并渲染为目标 rig 的 raster。**
2. **确认 RL 是否可行**：包括 action/plan 接口、环境交互和可用 reward；优先复用已有环境及默认 reward。
3. **可行后做相关工作调查，明确自己的贡献**：是否已有类似 sim/real 联合训练，以及三类学习目标的结合到底有什么差异。

因此不是把“我要从零写 reward function”单独立成研究贡献。佐藤明确倾向复用现有 reward；raster 构造与接入是需要自己完成的部分。

他在结尾建议 **multi-dataset / cross-rig alignment 与 simulator/RL 两个方向都探索**，并提出将来可能各成一篇论文。这是研究布局的可能性，不是已经确定的两篇论文交付承诺。

## 【需要我继续思考的问题】

### 1. External alignment 究竟迁移什么

- External real/raster pairs 学到的是可迁移的视觉对应，还是主要依赖 external rig 的几何关系？
- 它为什么能帮助 target rig，尤其是 target real 为零或极少时？
- 哪些模块共享、哪些信息需要按 rig 区分？Joint training 与蒸馏各自解决什么？

### 2. 为什么可能有效，为什么也可能失效

- 少量 target pair 的主要瓶颈是数量、场景覆盖，还是 rig 特有的视觉几何？
- 大量 external alignment 是否会压过 target 的需求？
- 增加 external-rig planning loss 是否真的造成干扰？

后两项是根据佐藤的担忧整理出的**待验证机制假设**，不是他已给出结论的具体因果解释。“数据不平衡”需要继续说清如何影响学习；不能停在比例很悬殊。

### 3. 如何严格定义实验条件

- 每种方法能看到哪些数据、标签和 calibration？
- Zero-shot 是否除去所有 target 训练场景信息，还是只限制 target RGB？
- Few-shot 的单位是多相机同步帧、单张相机图像、scene 还是驾驶时长？
- 如何区分 external 独立数据量增加与训练采样次数增加？

### 4. 哪项结果能构成方法贡献

- A/B 差异只是“多用一些 RGB”，还是有必要的跨 rig 对齐机制？
- 哪个 ablation 能证明该机制不可省略？
- 与相同训练资源下的原 RAP、BEV/3D 等方法相比，究竟多解决了什么问题？

### 5. Simulator/RL 路线是否值得深入

- 是否取得了足够的几何状态来构造 camera-view raster？
- Planner 的轨迹输出怎样接到 simulator 的 action 接口？
- 已有 reward、动力学和任务是否适合拟验证的能力？
- 先蒸馏还是直接 RL，哪一条能以更低成本给出有意义的证据？
- Sim/real 联合学习与已有方法的真实差分是什么？

## 【已经确定的事项】

这里“确定”指会上明确的设置或推进方向，不代表性能已获验证。

1. **最终面向固定 target rig 的 planning**，以降低 target 真实数据需求为核心目标。
2. **训练时知道 target rig 参数**；zero-shot 的明确计数对象是 target 真实训练图像。
3. **Camera rig 按相机数量、内参、外参来描述**；会上将 FOV/distortion 归在内参侧。
4. **External metadata 可以按 target rig 渲染，用于 target-view planning 学习**；不必取得同场景的 target RGB。
5. **以 External/Target 替代 Old/New**，避免把数据角色写成时间先后。
6. **重点考察 target 数据效率与 external 数据量收益**；表和图均可。
7. **External alignment 值得实验验证**，不预设 all-data 一定最强。
8. **当前优先设计将 planning 集中在 target rig**；external-rig planning 保留为可检验的消融。
9. **调查简易 simulator，优先复用已有 reward**，并确认 raster 化与 RL 接口。
10. **两条研究方向都继续探索**；最终方法、loss 权重、simulator 选型和论文拆分尚未确定。

## 【我从现在开始可以马上跑的实验】

以下是依据会议整理的执行方案，并非已经运行的结果。具体数据档位与运行顺序属于整理建议；可复用当前 RAP 代码的部分优先。

### A. 最小四格实验：把两类 external 知识拆开

先固定一个可运行的 target few-shot 子集、target 测试集、backbone 和基本训练配置。

| 编号 | Target 自身 real/raster 学习 | External metadata → target-view raster planning | External real/raster alignment | 主要回答 |
|---|---|---|---|---|
| E0 | 有 | 无 | 无 | Target-only 基线 |
| E1 | 与 E0 相同 | 有 | 无 | External planning knowledge 的增益 |
| E2 | 与 E0 相同 | 无 | 有 | External alignment knowledge 的独立增益 |
| E3 | 与 E0 相同 | 有 | 有 | 两者结合是否互补 |

E2 的“无”仅指**不把 external 场景用于额外 planning supervision**；生成 external raster 仍需相应 metadata。

**启动顺序建议：先 E0/E1；external alignment 分支具备后再跑 E2/E3。** 如果代码已经支持全部路径，可同时安排。不要为了等新分支完成而延后现成基线。

### B. 两项关键消融

- **E1 vs E1 去掉 target alignment**：保留其余数据及 planning supervision，检验 explicit alignment 的贡献。
- **E3 vs E3 加入 external-rig planning loss**：检验佐藤担心的干扰。这个对照是在相应分支具备后运行，不能把尚未写好的机制算作已经可跑。

### C. 两条数据规模轴，先少量点

- **固定 external，变化 target**：优先补 target real = 0 与一个 few-shot 条件，再扩展更多档位。Zero-shot 时关掉依赖 target real 的项，并单独标明是否保留 external alignment。
- **固定 target，变化 external**：先比较 external = 0 与一个非零预算，有余力再加较大预算。

尽量固定模型、训练更新预算及评估条件；记录各分支采样量，避免把“数据规模”与“训练更久”混为一谈。对关键差异补独立 seed 或 target 子集抽样；来不及重复时，明确标注 preliminary，不把单次小幅提升写成定论。

### D. RL 方向现在可做的最小验证

先做 **state → target-view raster → planner output → simulator 接口/reward** 的端到端可行性验证。

验收产物可以是少量正确的 raster、一次有效的环境步进与 reward 返回，以及尚缺的接口列表。它不等于完整 RL 性能实验；无需等待 teacher 或联合 RL 训练完成才向老师报告。
